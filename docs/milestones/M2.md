## Status

M2 is **Complete** for the revised Document Processing Foundation boundary.
The completed milestone retrieves retained sources through Storage, makes them
available to the processing provider through controlled transport, executes and
maps provider jobs, ingests and retains Raw Processing Result evidence, and
validates the integration through automated tests and controlled disposable
provider smoke.

M2 is not the current milestone. The current Roadmap and milestone index govern
current sequencing and downstream milestone states; they identify M4 — Smart
Reading OS as the current milestone.

The final completed M2 output is retained Raw Processing Result. Raw Result
interpretation, provider-independent normalization, and Structured Processing
Result continued in M3.

## Original Roadmap v2 goal

The historical Roadmap v2 M2 goal was to establish the document-processing
foundation that retrieves retained Sources through Storage, integrates
`paddle-vl-api`, normalizes provider output through MinerU-Popo, and produces a
structured processing output contract for M3.

This completion record preserves that original plan as historical scope. It does
not rewrite M2 as if it had always ended at Raw Processing Result retention.

## Completion summary

M2 completed the revised provider-integration and retained Raw Processing
Result boundary:

- retained Source access through Storage;
- provider-reachable source transport;
- provider-independent transport grant lifecycle;
- `paddle-vl-api` adapter/client behavior, request construction, job polling,
  progress mapping, status mapping, and error mapping;
- Raw Processing Result ingestion and Atlas-owned envelope retention;
- retained raw payload/evidence references, source references, provider
  references, outcome metadata, checksums, and provenance fields;
- non-persistent one-attempt provider-to-Raw-Result orchestration;
- end-to-end in-process integration from retained source through provider
  execution and Raw Result retention;
- disabled-by-default operator/smoke path for one controlled disposable live
  provider invocation;
- cleanup and grant revocation after the integration path; and
- controlled disposable live-provider smoke validation with documented evidence
  limitations.

## Final M2 output

Final completed M2 output: **retained Raw Processing Result** and associated
source, provider, outcome, payload, and provenance references.

The M2-to-M3 handoff object is retained Raw Processing Result evidence. M2
provides the retained source evidence, provider execution outcome, raw payload
reference, Raw Result checksum/size metadata when captured by the path, provider
job identifiers, source checksum linkage, and provenance references needed by
downstream interpretation.

M2 does not claim Structured Processing Result, durable Structured Content,
canonical Structured Content Version, Reader publication, or Reader-ready
projection as M2 output.

## M2-to-M3 handoff

M2 hands off retained Raw Processing Result evidence to M3. The handoff includes:

- retained source evidence and Storage references;
- provider execution outcome and provider job references;
- retained Raw Result payload references;
- source checksum and payload checksum evidence when captured;
- raw-result, source, provider, outcome, and provenance metadata needed by the
  downstream normalization layer.

M3 owns provider-independent interpretation of retained Raw Result evidence,
normalization, Structured Processing Result, recovery semantics, diagnostics,
fixtures, evidence mapping, and deterministic validation.

boundary. It does not, by itself, certify all providers or environments, approve
a release, or establish production readiness.

## Completion boundary and limitations

M2 Complete does not imply:

- Structured Processing Result was completed in M2;
- Raw Result interpretation or provider-independent normalization was completed
  in M2;
- durable Structured Content, SCV, canonicalization, Structured Document, or
  Reader publication exists as M2 output;
- production hardening is complete;
- all durable retry/idempotency persistence exists;
- M3, M4, or M5 completion state is established by this file;
- release authorization is granted;
- provider certification applies to every provider, deployment, or environment;
- controlled smoke evidence removes the need for future production operations,
  observability, security, and durability work.
