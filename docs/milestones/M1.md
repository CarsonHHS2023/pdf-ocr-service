## Goal

Establish the product, architecture, engineering, storage, source-retention,
deployment-limit, and processing-handoff foundation for Atlas while preserving
current runtime behavior and Reader compatibility.

## Scope

- product and architecture foundation;
- engineering governance, workflow, and CI;
- `Document` and `SourceFile` foundation;
- Alembic;
- Storage Adapter and Local provider;
- original Source retention mechanics;

- actual `paddle-vl-api` integration;

## Completed closeout task

### Storage Persistence Architecture and M1-to-M2 Processing Handoff

This documentation/design task did not implement the processing pipeline. It was
completed by [Atlas Persistence & Processing Foundation](../architecture/persistence-processing-foundation.md),
which defines the conceptual lifecycle from retained Source evidence through
Storage, processing, Structured Content, applications, and presentation.

#### Part A — Persistence Architecture

The foundation establishes:

- relational database vs Object Storage responsibilities;
- future derived indexes;
- `SourceFile` linkage;
- Artifact persistence;
- raw `paddle-vl-api` output responsibility;
- MinerU-Popo output responsibility;
- Structured Content persistence direction;
- Stream Text presentation/caching role;
- BLOB/Text migration direction;
- broken-reference handling through storage/source consistency boundaries;
- production durability as deferred hardening rather than completed M1 scope.

#### Part B — Processing Handoff

The foundation establishes:

- source retrieval through Storage;
- `paddle-vl-api` request/job/result responsibility boundaries;
- status/progress/error concepts for later processing implementation;
- raw result ownership by Processing;
- MinerU-Popo input role as processing normalization input;
- minimum M2 boundary as retained Raw Processing Result under the reconciled roadmap;
- provenance/version concepts;
- retry/idempotency concepts;
- M2/M3/M4 boundary alignment.

## Reconciled milestone boundary

M1 is the completed Foundation milestone. It provides the source/storage,
engineering, migration, deployment-limit, and processing-handoff foundation but
does not claim completion of later processing or Structured Content work.

As handoff context only, the current Roadmap and milestone index report these downstream boundaries:

- M2 is **Complete** at retained Raw Processing Result and controlled provider
  integration.
- Raw Result interpretation, normalization, and Structured Processing Result
  continued in M3.
- M3 is **Complete for revised scope** covering SPR v1, normalization, recovery
  semantics, diagnostics, evidence, fixtures, and deterministic validation.
- Durable Structured Content / SCV, Structured Document, canonicalization,
  Reader-ready projection, presentation consumption, and Recovery Presentation
  continue in M4.
- Stream Text and Reader serialization are presentation/compatibility formats,
  not canonical Structured Content.

## Compatibility constraints

change endpoint paths, Bookshelf-shaped responses, `book_id`, `image_id`, image
markers, current page expectations, or existing TXT/PDF reading behavior.
