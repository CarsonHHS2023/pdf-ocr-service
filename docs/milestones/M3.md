## Status

M3 is Complete for revised scope.

M3 is not the current milestone. Current sequencing and the current milestone are governed by the [Roadmap](../roadmap/roadmap.md) and [milestone index](README.md), which identify M4 — Smart Reading OS as the current implementation frontier. This M3 record preserves M3 scope history, explains the revised completion boundary, records task dispositions, and documents the M3-to-M4 transfer. It does not authorize M4 task order, M4 completion status, release status, or production readiness.

## Original goal

The original Roadmap v2 goal for M3 — Document Core & Structured Content Foundation was broader than the slice ultimately completed in M3. It aimed to establish provider-independent interpretation of retained processing evidence and durable, evidence-linked Structured Content so M4 Smart Reading OS and M5 Smart Archive could consume selected provider-independent content rather than provider JSON, Raw Result storage locations, or provider job state.

## Completion model

M3 completion is scope-qualified because the original Roadmap v2 M3 scope moved in two directions during implementation:

1. **M2 → M3 incoming transfer:** M2 completed at retained Raw Processing Result. Raw Result interpretation, provider-independent normalization, Structured Processing Result, recovery semantics, diagnostics, fixtures, evidence linkage, and deterministic validation continued in M3.
2. **M3 revised completion:** M3 completed the provider-independent SPR v1, Paddle-VL Raw Result → SPR normalization, fixture validation, recovery and diagnostic, topology/evidence preservation, provider-conformance-support, and deterministic serialization/validation slice.
3. **M3 → M4 outgoing transfer:** durable Structured Content / SCV, Document Core persistence, canonicalization and acceptance/version lifecycle, Structured Document assembly, Reader-ready projection, presentation projection, and Reader/API consumption from the Structured Content boundary were not completed in M3. They continue in the M4 implementation frontier.

M3 did not complete its entire original Roadmap v2 scope. Transferred work remains real project work and is not declared completed by this milestone record.

## Completion summary

The completed M3 boundary is:

```text
Retained Raw Processing Result
→ provider-independent interpretation and normalization
→ Structured Processing Result v1
```

The current downstream target boundary is:

```text
Structured Processing Result
→ Structured Content / Structured Document
→ presentation / Reader / API consumers
```

M3 delivers a persistence-neutral, provider-independent normalized processing representation with deterministic validation and serialization, Paddle-VL mapping support, safe diagnostics, recovery semantics, fixture-backed evidence, topology preservation, and provider-conformance support. M3 does not define SPR as canonical application content.

## Original M3 scope

Original M3 planning included these responsibilities:

- provider-independent Structured Processing Result;
- ProcessingRun persistence;
- Observation persistence;
- Evidence persistence or durable evidence linking;
- Structured Content schema;
- Structured Content Version / SCV;
- canonical content selection, acceptance, and version lifecycle;
- Structured Content builder / Structured Document assembly;
- content-node or block ordering;
- assets and evidence linkage;
- retained Raw Result → Structured Content verification;
- Reader-compatible consumption path;
- provider-output isolation from application content.

## Revised completed M3 scope

The revised completed M3 scope includes only the implemented and evidenced slice below:

- Structured Processing Result v1 Contract;
- provider-independent SPR runtime/model;
- deterministic SPR validation and serialization;
- Paddle-VL `full` profile and `v1.6` Raw Result → SPR normalizer;
- fixture inventory and committed synthetic validation corpus;
- provider identity, profile, revision, payload size, checksum, unsafe-metadata, terminal-status, page-mapping, block, and reference validation;
- page topology preservation, source-page mapping, node ordering, page roots, and evidence ordering;
- node, normalized-observation, and evidence-link relationships;
- source/provider provenance and evidence references inside the runtime SPR representation;
- page-level `NO_USABLE_SEMANTIC_CONTENT` diagnostics;
- document-level `PARTIAL_DOCUMENT_RECOVERY` diagnostics;
- partial-recovery semantics and safe no-SPR diagnostic behavior;
- provider-conformance support through SPR, recovery, and provider-conformance documentation and tests.

Provider-conformance support means documented contract/profile/reference and validation support. It does not mean provider certification, universal provider compatibility, release authorization, or production readiness for every provider and environment.

## M3-to-M4 handoff

M3 hands M4:

- retained Raw Result interpretation rules;
- provider-independent SPR v1;
- deterministic normalized representation;
- page topology and source-page mapping;
- nodes, normalized observations, and evidence references;
- provider/source provenance references;
- recovery facts, warnings, and diagnostics;
- partial-recovery semantics and safe no-SPR failure diagnostics;
- fixture-backed validation and provider-conformance support.

M4 must build downstream:

- durable Structured Content / SCV where required;
- Structured Document assembly;
- Document Core persistence where required;
- canonical content selection and acceptance/version lifecycle;
- presentation and Reader-ready projections;
- Reader/API consumption from the Structured Content / Structured Document boundary.

## Architecture boundary

Raw Processing Result is retained provider evidence, not application content. SPR is provider-independent normalized processing output, but SPR is not canonical Structured Content. Reader should not consume provider JSON as canonical truth, and the architectural boundary is not SPR directly to Reader. Reader, presentation, API consumers, Smart Reading OS, and Smart Archive should consume projections from Structured Content / Structured Document.

## Recovery and diagnostics

M3 may claim completion of runtime recovery facts, recovery diagnostics, partial-recovery semantics, safe warning output, page-level no-usable-semantic-content diagnostics, and document-level partial-recovery diagnostics in the SPR/runtime/normalizer boundary.

M3 does not claim completion of full Recovery Presentation UI, Reader rendering behavior, final presentation projection, all M4 recovery work, or a release-ready user experience.
