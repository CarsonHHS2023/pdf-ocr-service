## 2. Milestone goal

Deliver the smallest stable repeated-use Reader experience over selected Structured Content / Structured Document foundations, supporting:

- general reading;
- basic Speed Reading;
- deterministic navigation/location identity;
- bounded content delivery for large documents;
- image/table behavior with safe degradation;
- honest recovery/loading/failure presentation;
- lexical in-document find;
- reopen/revisit/lifecycle behavior;
- explicit compatibility and supported-format boundaries.

M5 is not the complete Smart Reading OS. Evidence-backed summaries, Q&A, Flashcards, Mind Map, broader AI Tutor/RAG, and semantic search remain M6 or later scope. Smart Archive remains M7.

## 3. Architectural boundary

```text
Source / Processing Evidence
  -> Raw Processing Result
  -> Structured Processing Result (SPR)
  -> selected Structured Content / Structured Document
  -> Reader application view / projection
  -> bounded Reader API
  -> Reader client
  -> general reading + Basic Speed Reading
```

Reader presentation must not redefine canonical content. Provider JSON, raw processing payloads, SPR, transient URLs, local filesystem paths, legacy `PdfPage`/`BookImage`/`MineruResult`, and Reader serialization are not canonical Reader truth.

The target platform scalability architecture additionally preserves the following ownership:

```text
Neon PostgreSQL     = business/Reader relational state
Object Storage      = source and immutable binary/artifact plane
Modal               = retryable elastic compute plane
Backend             = thin business/control/finalization plane
```

See [Scalable Storage and Processing Architecture](../architecture/scalable-storage-and-processing-architecture.md).

## 5. Required M5 scope

### 5.1 Reader application/projection consumption

Reader consumes explicitly selected canonical content through a defined application/projection boundary with stable candidate/version identity, deterministic ordering, source-unit/page/node identity as applicable, evidence/recovery references where required, and versioned compatibility behavior.

### 5.2 Bounded Reader API

Reader metadata/navigation is separable from bounded content delivery. The client must not assume an entire large document arrives in one response, and assets may load lazily.

### 5.3 General reading

Supported documents render readable ordered headings/paragraphs and supported visuals/tables, with safe degradation for missing/unsupported assets and deterministic reopen behavior.

### 5.4 Basic Speed Reading

M5 includes deterministic text segmentation/playback with start, pause, resume, stop, speed adjustment, previous/next or equivalent navigation, and return to normal reading. Advanced AI pacing/coaching is excluded.

### 5.5 Navigation and location

Reader provides deterministic page/source-unit/heading/node navigation as applicable and stable location identity bound to the selected content version.

### 5.6 Images, tables, and formulas

Supported Reader visuals/tables/formulas render through canonical asset/content references or degrade safely. M5 does not fabricate semantic table content or infer missing visual content.

### 5.7 Recovery Presentation

The Reader distinguishes content readiness, partial/degraded recovery, no usable semantic content where applicable, processing/loading/unavailable states, and failures without exposing raw provider diagnostics as product truth.

### 5.8 Lexical find

M5 requires deterministic in-document lexical find over explicitly supported fields, with results mapped back to stable locations. Semantic retrieval belongs to M6.

### 5.9 Reopen, revisit, and lifecycle

M5 defines deterministic reopen/revisit behavior and the relationship between Reader-visible removal, derived client/cache state, selected content, source evidence, and retention. Shared physical artifacts must not be deleted merely because one logical user Document is removed.

### 5.10 Supported formats and large documents

M5 must exit with an explicit tested support matrix and known limitations. Current evidence supports PDF/TXT direction, but the completion review must record the final claim. Large-document behavior must remain bounded and measured.

## 9. Completion / exit criteria

The following 22 criteria remain the milestone completion checklist. Evidence status is maintained in the latest progress/completion review rather than assumed from code presence.

1. Reader consumes approved selected Structured Content / Structured Document through the application/projection boundary.
2. Reader does not use provider JSON, Raw Result, SPR, or legacy tables as canonical product content.
3. A supported document can be opened and read repeatedly through stable contracted behavior.
4. Supported ordering and hierarchy render deterministically.
5. Navigation works for the approved scope.
6. Basic Speed Reading consumes stable content segments and provides the approved controls.
7. Images/tables/formulas render or degrade safely according to documented support.
8. Recovery Presentation distinguishes supported complete/partial/degraded/unavailable/failed states.
9. Lexical find produces deterministic matches linked to stable content locations.
10. Reopen/revisit behavior is deterministic for selected/current content identity.
11. Delete/cleanup behavior is documented and tested without violating source/artifact retention.
12. Current/legacy Reader compatibility has a documented retain/version/migrate/deprecate rule.
13. Supported document-type claims are explicit and tested.
14. Large supported documents do not depend on an unbounded response assumption.
15. Failure/loading/unavailable states are deterministic and user-safe.
16. Optional Notes/highlights are explicitly deferred or implemented with approved identity/ownership/version/retention/access rules.
17. Tests cover required general reading, Speed Reading, navigation, assets, recovery, search, reopen/delete, compatibility, and invalid states.
18. M5 limitations and non-goals are documented.
19. Internal technical-demo evidence does not masquerade as external release readiness.
20. External pilot/commercial claims remain blocked unless the separate gate is satisfied.
21. M6 can consume stable content, Reader, evidence, and navigation foundations without changing canonical assumptions.
22. Completion evidence is recorded before Milestone Status changes from In Progress to Complete.

Criterion 22 is not yet satisfied. Therefore M5 remains In Progress.

## 10. Validation strategy for completion review

The final completion review should aggregate exact commit/PR/test evidence across both repositories for:

- application contract and forbidden-dependency boundaries;
- Reader API bounded delivery;
- ordering/hierarchy/navigation/location;
- Reader rendering and asset/table/formula degradation;
- Recovery Presentation;
- Basic Speed Reading;
- lexical find;
- reopen/revisit/delete semantics;
- PDF/TXT support and limitations;
- large-document measurements;
- invalid/loading/failure states;
- compatibility/deprecation posture;
- keyboard/accessibility behavior;
- controlled integrated Reader demonstration.

Screenshots, a one-time demo, successful OCR alone, or a database migration alone are insufficient to complete M5.

## 11. External pilot/commercial gate

The external gate remains separate from M5 status. Before external/public/commercial claims, Atlas still requires appropriate authentication, authorization, user/tenant ownership, durable processing status, retry/idempotency, secure storage/deployment, quotas/cost controls, observability, backup/restore, retention/deletion policy, privacy/security review, and incident/failure recovery.

The S0–S9 scalability track is designed to advance these properties but does not silently authorize an external release.

## 12. M5 -> M6 handoff

M6 may depend on:

- stable selected Structured Content identity;
- stable Reader application contract/location identity;
- evidence/source anchors and recovery state;
- supported asset references;
- deterministic Reader fixtures;
- explicit supported-format/limitation declarations;
- ownership/security context where user-specific features require it;
- provider-independent SPR/content boundaries.

M6 must not require M5 to implement chapter summaries, Q&A, Flashcards, Mind Map, AI Tutor, semantic search, RAG, or embeddings.
