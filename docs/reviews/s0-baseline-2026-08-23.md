## 1. Decision

S0 is **not complete** yet.

Atlas now has enough durable lifecycle state to establish a repeatable baseline process, but the currently retained Staging database does not contain enough durable measurements to support all S0 claims. This report therefore separates:

1. values that can be measured directly from retained authoritative rows;
2. observability signals that exist but are not equivalent to a required S0 metric;
3. metrics that are still not durably instrumented.

Missing measurements are not inferred from unrelated logs or timestamps. A bounded event window is explicitly reported as `partial` for event-derived aggregates; a `retryable=true` diagnostic signal is never counted as proof that a retry attempt occurred.

## 4. Measurement harness added by this S0 slice

The repository now contains a read-only collector and operator CLI:

```text
app/processing/s0_baseline.py
scripts/report_s0_baseline.py
```

Example operator usage in an environment with the intended `DATABASE_URL`:

```bash
python scripts/report_s0_baseline.py \
  --processing-run-id <run-id> \
  --format markdown \
  --output /tmp/s0-run.md
```

Multiple `--processing-run-id` values may be supplied to produce a comparison collection. The tool:

- reads only durable database state;
- emits no document title or filename;
- preserves exact source checksum only in operator output for private replay identity;
- marks missing required metrics explicitly;
- marks event-derived aggregates `partial` when the bounded event window is truncated;
- keeps error-severity/retryability signals auxiliary rather than promoting them to failure/retry counts;
- bounds durable event loading per run;
- exposes generic numeric event-field inventory without silently promoting fields to unrelated S0 claims.

The collector does not write to the database, object storage, Provider, Modal, or Reader state.

## 5. Next S0 evidence pass
